# Section 1: Task 1 — Pretrained-Model Egg Segmentation

## 1.1 Objective

The goal of Task 1 was to segment individual eggs in a dataset of real-world photos using pretrained, off-the-shelf models — no custom training or fine-tuning. The output of this task (instance masks) serves two purposes downstream: it is treated as **ground truth** for evaluating the classical algorithm built in Task 2 (see Task 3), and it establishes the dev/eval split reused throughout the project.

## 1.2 Pipeline

A two-stage, zero-shot detect-then-segment pipeline was used:

1. **Detection — OWL-ViT (open-vocabulary object detector).** Each image is passed through OWL-ViT with the text prompt `"egg"`. OWL-ViT is a text-prompted detector, able to localize objects matching a natural-language description without being trained specifically on eggs. This produces bounding boxes around candidate egg regions, with confidence scores.
2. **Segmentation — SAM (Segment Anything Model), box-prompted.** Each OWL-ViT bounding box is passed as a prompt into SAM, which produces a precise pixel-level instance mask for the object inside that box.

This combination allows fully automatic, label-free instance segmentation: OWL-ViT answers "where are the eggs," and SAM answers "what exactly are their pixel boundaries."

A lightweight **fallback mechanism** supplements primary OWL-ViT detections: when the primary detector's output is missing or low-confidence for an image, a fallback box-proposal step (`source: fallback-1` in `review_list.txt`) supplies a substitute box, and the image is automatically flagged for manual review so this substitution is never silent.

## 1.3 Dataset and Train/Eval Split

The dataset (Roboflow export, egg images across varied backgrounds — hands, trays, marble, cloth, keyboards, leaves, etc.) contains 110 total images after de-duplication of Roboflow's augmented copies.

To prevent data leakage (Roboflow's augmentation pipeline can produce multiple near-duplicate copies of the same original photograph), images were grouped by **original source photo** before splitting, and a 4:1 grouped split was applied:

- Total images: **110**
- Dev set: **88** images
- Eval set: **22** images

This exact split (recorded in `task1_outputs_final/split.csv`) is reused unchanged in Task 2, so the classical algorithm is developed and evaluated on the same images as the pretrained pipeline, making the Task 3 comparison fair.

## 1.4 Outputs

For each image, the pipeline produces:

- `masks/` — binary instance mask(s), one per detected egg
- `labels/` — class/instance label files
- `instances/` — per-instance crops/metadata
- `overlays/` — the original image with mask(s) drawn on top, for visual QA
- `diagnostics/` + `review_list.txt` — images flagged for manual review (fallback detections or manually-corrected boxes, `source: fallback-1` / `source: manual`)
- `results.csv` — per-image summary

## 1.6 Notes and Limitations

- As a zero-shot pipeline, quality depends on OWL-ViT's detection recall/precision for the word "egg." A fallback mechanism catches _some_ low-confidence cases and flags them for review (Figure 3), but is not a complete safety net: Figure 4 shows a confidently-wrong mask (tissue paper mistaken for an egg) that passed through **unflagged**, meaning the review process does not catch 100% of real failures. Any downstream use of Task 1 outputs as "ground truth" (as done in Task 3) should account for this small number of unflagged errors.
- Multi-instance images (multiple eggs in frame) are handled naturally since OWL-ViT can return multiple boxes per image, each independently segmented by SAM — this differs materially from Task 2's classical pipeline, which has no native multi-instance handling (discussed in Task 3).
- No console logs/timing/threshold values were retained from the original run beyond the split statistics above; this section is written from the saved outputs (`split.csv`, `review_list.txt`, overlays) rather than run logs.

# Section 2: Task 2 — Classical Image-Processing Egg Segmentation

## 2.1 Objective

The goal of Task 2 was to build a **classical (non-deep-learning) image-processing algorithm** that segments eggs as closely as possible to the quality of Task 1's pretrained OWL-ViT + SAM pipeline, using only traditional computer vision techniques (thresholding, edge detection, color-space operations, morphological operations, etc.) — no neural networks, no learned weights.

To keep the comparison in Task 3 fair, Task 2 reuses **the exact same dev/eval split** established in Task 1 (`task1_outputs_final/split.csv`: 110 total images, dev=88, eval=22). All development and trial-and-error below was performed by inspecting results on the **dev set only**; the eval set was not used to tune any parameter, and the final locked-in algorithm was simply run once over the full 110-image dataset for reporting.

It was expected going in — and is confirmed by Task 3's quantitative analysis — that a classical pipeline would **not** match SAM's pixel-level accuracy. The goal was to get as close as a classical approach reasonably can, build genuine intuition about _why_ it falls short, and document that gap rigorously. That gap is the subject of Task 3.

## 2.3 Final Algorithm (Locked In)

The final pipeline, implemented in `task2_segment_eggs.py`, is:

1. **Soft-trimap-seeded GrabCut** — a bounding box similar in spirit to Task 1's detection box is used to build a trimap: only the border region outside the box is marked hard background (`GC_BGD`); everything inside is left as "probable" foreground/background for GrabCut to resolve iteratively. No hard foreground core is used (this was the key fix over Trial 7).
2. **One-time adaptive retry** — if the resulting foreground covers more than 55% of the frame (a strong signal that bleed/inversion occurred), the box is tightened and GrabCut is re-run once.
3. **Saturation-gated YCrCb skin removal** — pixels falling in a skin-colored YCrCb range are removed from the foreground, but only above a saturation threshold, to avoid misclassifying pale/low-saturation egg highlights as skin.
4. **Morphological opening** (kernel ≈2% of image diagonal) to break thin background-bleed "necks" connecting the true egg region to adjacent similarly-colored background.
5. **Centroid-based component selection** — among the remaining connected components, the one whose centroid is closest to the image center is kept (not the largest by area), since area-based selection is vulnerable to picking an unrelated large background region.
6. **Hole-filling** to produce a clean, solid final mask.

Output structure mirrors Task 1 (`task2_outputs_final/masks/`, `labels/`, `instances/`, `overlays/`, `results.csv`, `review_list.txt`), with `results.csv` additionally logging `area`, `frame_frac`, `retried`, `flagged`, and `flag_reason` per image for transparency.

## 2.4 Full-Dataset Results

The final script was run once over the complete 110-image dataset (both dev and eval), with no crashes:

- **110/110 images processed successfully**
- **39/110 (35.5%) flagged for review**, predominantly due to suspected background bleed (foreground fraction outside expected range)
- **2/110 complete failures** (area = 0, i.e. the pipeline found nothing to segment):
  - a three-eggs-on-marble scene, where the low-contrast marble background and multiple separate egg instances defeated the single-component-picking design
  - a hand+egg scene on a low-contrast tile floor
- An additional confirmed qualitative failure: a foil snack packet fused with the egg through a thick color-similarity "neck," surviving the morphological opening step due to its width (the same wide-neck ceiling noted in Trial 9)

## 2.5 Known Limitations

- **No native multi-instance handling.** By design, the pipeline selects exactly one connected component per image. Scenes with multiple eggs will have at most one correctly captured; this is a structural limitation, not a tunable parameter, and is the dominant root cause behind several of Task 3's failure categories (see Section 3.3.1).
- **Global color-model bleed.** GrabCut's foreground/background color model is global per image; when the egg's color is statistically similar to a large part of the background (ash/rock, pale tile, marble, cloth), the foreground region can bleed into or fuse with that background. The morphological-opening fix (Trial 9) only resolves this when the connecting "neck" is thin; wide necks are a confirmed, accepted failure mode.
- **No semantic understanding of "egg."** Unlike Task 1's OWL-ViT detector, the classical pipeline has no concept of what an egg looks like — it relies entirely on local color/contrast structure and a seed region. This means it can confidently segment a non-egg object (e.g. a round shadow, a patterned fold, a packaging graphic) if that object's color statistics happen to separate well from its local surroundings.
- **Parameter choices were tuned on the dev set by visual inspection**, not through formal grid search or cross-validation — consistent with the trial-and-error, "build and diagnose" approach used throughout, and documented transparently above rather than presented as an optimized result.
